# 05 — หน่วยความจำ ข้อจำกัด และวิธีแก้

ESP32-S3 Super Mini ใช้ชิป **ESP32-S3FH4R2**: flash 4 MB, SRAM 512 KB (เหลือให้แอป ~320 KB)
โปรเจกต์นี้ **ไม่สมมติว่ามี PSRAM** — โค้ดรันได้บนบอร์ดที่ไม่มี PSRAM และจะใช้ PSRAM ให้เองถ้าเปิด build flag

## 1. ตัวเลขที่วัดได้จริงจากการ build นี้

| รายการ | ค่า | หมายเหตุ |
|--------|----:|----------|
| Flash ที่ใช้ (sketch) | **385,525 B** | 12.3% ของ 3,145,728 B (partition `huge_app` 3 MB) |
| Static RAM (`.bss`+`.data`) | **29,780 B** | 9.1% ของ 327,680 B |
| Sample pool (ค่าเริ่มต้น) | 150,000 B | จองครั้งเดียวตอนบูต ไม่มี malloc ระหว่างเล่น |
| ชุดเสียงทดสอบ 1 ชุด | **131,856 B** | 5.97 s ที่ 22 050 Hz แบบ u-law = 88% ของ pool |
| Voice state | ~290 B | 12 voices × 24 B |
| I2S DMA buffers | 1,536 B | 3 × 128 frames × 4 B (สเตอริโอ 16-bit) |
| Task stacks | 16 KB | audio 4K + trigger 4K + loop 8K |
| **Heap ที่เหลือ (คาดว่า)** | **~20–40 KB** | ตรวจด้วยคำสั่ง `m` ใน serial |

> ค่า heap ที่เหลือเป็นค่าประมาณจากการคำนวณ ไม่ได้วัดบนฮาร์ดแวร์จริง —
> เปิด serial monitor แล้วพิมพ์ `m` ดูค่าจริงก่อนตัดสินใจเพิ่มขนาด pool

## 2. ทำไมเลือก u-law 8-bit

| รูปแบบ | ต่อ 1 วินาที | ชุดทดสอบ 5.97 s | คุณภาพ |
|--------|-------------:|----------------:|--------|
| 16-bit PCM 22 050 Hz | 44.1 KB | 263 KB → **ไม่พอ** | ดีที่สุด |
| **u-law 8-bit 22 050 Hz** (ค่าเริ่มต้น) | **22.05 KB** | **132 KB → พอ** | เทียบเท่า ~12 bit ในย่านที่ได้ยิน |
| u-law 16 000 Hz | 16 KB | 96 KB | ฉาบทึบลงชัดเจน |
| u-law 32 000 Hz | 32 KB | 191 KB → ไม่พอ | ฉาบใสขึ้น |

u-law เป็นการบีบอัดแบบ logarithmic มาตรฐานโทรศัพท์ (G.711) — ให้ SNR ~38 dB ซึ่งสูงกว่า
noise floor ของ piezo pickup อยู่แล้ว การเข้ารหัสทำตอนโหลดชุดเสียง (ไม่ใช่ตอนเล่น)
จึงไม่กิน CPU เลยระหว่างเล่น เปิด 16-bit ได้ด้วย `-DAUDIO_16BIT=1` (แต่ต้องใช้ pool ~300 KB ซึ่งไม่พอใน SRAM)

## 3. Polyphony — เล่นพร้อมกันได้กี่เสียง

| ค่า | ค่าเริ่มต้น | ปรับได้ที่ |
|-----|------------:|-----------|
| จำนวน voice ทั้งหมด | **12** | `AUDIO_MAX_VOICES` |
| จำนวน instance ต่อแพด | 2 | `PADS[].maxVoices` |

พฤติกรรมเมื่อเต็ม:
1. ถ้าแพดเดิมถูกตีซ้ำ → ใช้ voice เก่าสุดของแพดนั้นซ้ำ (ไม่ไปแย่งแพดอื่น) — เป็นธรรมชาติของกลองจริง
2. ถ้า voice เต็มจริง ๆ → ขโมย voice ที่เล่นไปไกลที่สุด (เงียบที่สุดโดยธรรมชาติ) และนับใน `stolenCount`

**ภาระ CPU:** 12 voices × 22 050 Hz = 265,000 samples/s (คูณ + shift ต่อ sample)
บน 240 MHz ถือว่าเบามาก — เพิ่มเป็น 24 voices ได้สบาย (แก้ `AUDIO_MAX_VOICES` เป็น 24 ใช้ RAM เพิ่มแค่ ~290 B)
ข้อจำกัดจริงคือ "เสียงจะมั่ว" ไม่ใช่ CPU

## 4. ข้อจำกัดที่ต้องรู้ และวิธีแก้

| ข้อจำกัด | ผลกระทบ | วิธีแก้ |
|----------|---------|--------|
| ไม่มี PSRAM → pool ~150 KB | ชุดเสียงได้ ~6.8 วินาทีรวม | เปิด build `esp32s3-psram` (pool 1.4 MB ≈ 60 s) หรือย่อตัวอย่างให้สั้นลง |
| 22 050 Hz (Nyquist 11 kHz) | ฉาบ/ไฮแฮทขาด "อากาศ" | เปลี่ยน `AUDIO_SAMPLE_RATE` เป็น 32000 แล้วลดความยาวตัวอย่าง หรือเปิด PSRAM |
| ชุดเสียงโหลดใหม่ทั้งชุดตอนเปลี่ยนคิท | เงียบ ~0.3–1 วินาที ตอนเปลี่ยนคิท | ยอมรับได้ (เปลี่ยนคิทไม่บ่อย) หรือเพิ่ม PSRAM เพื่อ cache 2 ชุด |
| 12 voices | ตีพร้อมกัน 9 แพด + ตีซ้ำแล้วอาจขโมย voice | เพิ่ม `AUDIO_MAX_VOICES` |
| MCP3208 มี 8 ช่อง/ตัว | 1 ตัวไม่พอสำหรับ 9 แพด + pedal | ใช้ 2 ตัว (ค่าเริ่มต้น) หรือดู `docs/02-wiring.md` ข้อ 6 |
| อ่าน ADC ได้ ~1.7 kHz/ช่อง | peak ของ piezo บางครั้งคลาดได้ ~5% | มี peak-hold ฝั่งแอนะล็อกแล้ว (τ=10 ms) จึงพอ |
| ไม่มี OTA | ต้องต่อสาย USB เพื่อ flash | ตั้งใจ (partition 3 MB ให้โค้ด ไม่เสียที่ให้ OTA) |

## 5. ทำไมไม่อ่านไฟล์ WAV จาก SD ตอนเล่น (และนี่คือเหตุผลของสถาปัตยกรรม)

ถ้า stream จาก SD ตอนเล่น:

| ตัวเลข | ค่า |
|--------|-----|
| 1 voice (16-bit 22 050 Hz) | 44.1 KB/s |
| 10 voices พร้อมกัน | **441 KB/s** |
| SPI SD 20 MHz (ทฤษฎี) | ~2 MB/s → พอ |
| แต่....การอ่านจาก 10 ไฟล์สลับกัน | ต้อง seek ไปมา, block read 512 B, FAT lookup |

ปัญหาจริง: **latency ของ SD ไม่คงที่** (บาง block ใช้ 2–5 ms, บางครั้งมี spike 20 ms
ตอน wear-leveling) → ring buffer จะ underrun → ได้ยิน "แป๊ก" ซึ่งเป็นสิ่งที่โจทย์ห้ามไว้

ทางออกที่เลือก: **โหลดเข้า RAM ทั้งชุดตอนเลือกคิท** แล้วเล่นจาก RAM ล้วน ๆ
- ไม่มีการแตะ SD card ระหว่างเล่น → ไม่มีทางสะดุดเพราะ SD
- latency เริ่มเสียง = ไม่มี (แค่ copy pointer)
- แลกมาด้วย RAM 132 KB ต่อชุด ซึ่งเป็นงบที่รับได้บน 320 KB

## 6. Latency ทั้งระบบ

```
ตีแพด ──► piezo rise ~1-2 ms ──► trigger detect 2-4 ms (peak window 6 ms max)
      ──► คิวเสียง (ทันที) ──► mixer 1 block 5.8 ms ──► DMA 3 blocks 17.4 ms ──► DAC
                                                  รวม ~20-23 ms
```

ปรับให้เร็วขึ้นได้ (แลกกับโอกาส underrun):

| ค่า | latency | หมายเหตุ |
|-----|--------:|----------|
| `AUDIO_DMA_DESC_NUM 3`, `BLOCK 128` (ค่าเริ่มต้น) | 17.4 ms | ปลอดภัย |
| `AUDIO_DMA_DESC_NUM 2`, `BLOCK 128` | 11.6 ms | แนะนำถ้าไม่เจออาการเสียงแตก |
| `AUDIO_DMA_DESC_NUM 2`, `BLOCK 64` | 5.8 ms | เสี่ยง underrun ถ้าโค้ดช้า |

## 7. ตรวจสอบการใช้หน่วยความจำด้วยตัวเอง

```
m           # heap / pool / flash
s           # สถิติต่อวินาที (voices, adc rate, drops)
i           # ข้อมูลระบบทั้งหมด + threshold ทุกช่อง
```

ถ้า `heap` เหลือน้อยกว่า ~15 KB ให้ลด `AUDIO_POOL_BYTES` ลง (ระบบจะ fallback เองเป็น 3/4 และ 1/2 ของค่าที่ตั้งไว้
ถ้าจองไม่สำเร็จ) หรือใช้ `esp32s3-psram` build
