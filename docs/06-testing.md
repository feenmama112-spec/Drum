# 06 — วิธีทดสอบระบบทีละส่วน

ทดสอบตามลำดับ ห้ามข้าม — ถ้าขั้นไหนไม่ผ่าน อย่าเพิ่งไปขั้นถัดไป

## ขั้นที่ 0 — ทดสอบบนคอมพิวเตอร์ (ไม่ต้องมีฮาร์ดแวร์)

```bash
bash tests/host/run_tests.sh
```

ต้องได้

```
=== 2348 checks passed, 0 failed ===
...
PASS
```

ชุดทดสอบนี้ตรวจ logic จริงของเฟิร์มแวร์ (bit alignment ของ MCP3208, การบีบอัด u-law,
การ parse WAV, resample, peak detection/velocity, hi-hat zone, polyphony)
และตรวจว่าไฟล์ WAV ทั้ง 48 ไฟล์โหลดผ่านโค้ดเดียวกับที่รันบนชิปได้จริง

## ขั้นที่ 1 — บอร์ดเปล่า + USB

1. ต่อ USB-C เข้าคอมพิวเตอร์
2. เปิด serial monitor 115200
3. ควรเห็น

```
==================================================
  ESP32-S3 DIY ELECTRONIC DRUM MODULE  v1.0
==================================================
cpu 240 MHz  flash 4 MB  heap xxx kB  cores 2
```

ถ้าไม่เห็น log → ตรวจ `USB CDC On Boot` หรือกด BOOT ค้างแล้วเสียบ USB ใหม่

## ขั้นที่ 2 — จอ OLED

ต่อตาม `docs/02-wiring.md` หัวข้อ 2.5 แล้วรีเซ็ต

| ผล | ความหมาย |
|----|-----------|
| เห็น "DRUM MODULE / starting..." | ผ่าาน |
| จอไม่ติด, serial ขึ้น `[ui] SSD1306 not found` | ผิด address (ลอง 0x3D) หรือ SDA/SCL สลับ |
| จอติดแต่ตัวหนังสือกลับหัว | ตั้ง `display_.setRotation(2)` ใน `ui_oled.cpp` |

## ขั้นที่ 3 — SD card

1. คัดลอกโฟลเดอร์ `sdcard/` ลงการ์ด FAT32 (ต้องได้ `/DRUM/POP/`, `/DRUM/ROCK/`, ...)
2. เสียบการ์ด รีเซ็ต

```
[sd] mounted SDHC, 7625 MB total
[kit] SNARE.wav        449 ms    9922 B  peak  -1 dBFS
...
[kit] ROCK: 12/12 samples, 128 kB, 6.0 s
```

| อาการ | สาเหตุ |
|-------|--------|
| `[sd] mount failed` | การ์ดไม่ใช่ FAT32 / สาย MISO-MOSI สลับ / ไฟไม่พอ |
| `[kit] missing ...` | โฟลเดอร์หรือชื่อไฟล์ผิด (ตัวพิมพ์ใหญ่ทั้งหมด!) |
| `[kit] invalid WAV` | ไฟล์ไม่ใช่ PCM 16-bit (เช่นเป็น MP3 หรือ 24-bit) |

## ขั้นที่ 4 — เสียง (I2S + PCM5102A) **ยังไม่ต้องมี piezo**

1. ต่อ DAC ตามหัวข้อ 2.4 (SCK→GND, FMT→GND, XSMT→3V3 สำคัญมาก)
2. ต่อ PAM8403 + ลำโพง
3. ที่หน้า HOME กด **MENU** → เลือก `TEST PAD` → กด **MENU** อีกครั้งเพื่อเล่นเสียง

| อาการ | ตรวจ |
|-------|------|
| เงียบสนิท | XSMT ไม่ได้ HIGH / FMT ไม่ได้ลง GND / SCK ไม่ได้ลง GND |
| มีแต่ noise | BCK กับ LRCK สลับกัน |
| เสียงช้า/ต่ำ | sample rate ไม่ตรง — ดู `[audio] OK 22050 Hz` |
| เสียงแตก | ดู `i2s err` ใน `s` — ถ้าเพิ่มตลอดแปลว่า DAC ไม่รับ clock |

## ขั้นที่ 5 — บัส ADC (MCP3208)

ต่อ ADC ตามหัวข้อ 2.2/2.3 **โดยยังไม่ต่อ piezo** (ให้ CH ลอยหรือต่อ GND ผ่าน 10 kΩ)
แล้วพิมพ์ `i`

```
  adc        OK  1700 Hz scan
  pad        adc     threshold  peak
  SNARE      0:0      120        0
```

| อาการ | สาเหตุ |
|-------|--------|
| `adc NO RESPONSE` | MISO ไม่ต่อ / CS ผิดขา / ไม่มีไฟ 3.3 V ที่ VDD+VREF |
| ค่าทุกช่องเป็น 4095 | VREF ไม่ต่อ หรือ входลอยขึ้นไปที่ราง |
| ค่าแกว่งมากตอนไม่มีอะไรแตะ | ยังไม่ได้ต่อวงจร piezo (ปกติ) — ต่อวงจรก่อน |

## ขั้นที่ 6 — Piezo 1 ช่อง (Snare)

1. ต่อวงจร `docs/04` 1 ช่องเข้า CH0 ของ chip #0
2. พิมพ์ `t` เพื่อดูค่า peak สด ๆ 3 วินาที
3. เคาะที่ piezo

```
[adc] SNARE=1240 SNARE RIM=8 ...
```

- ตัวเลขต้องกระโดดตามแรงเคาะ (เบา ~300, แรง ~3000)
- ถ้าไม่ขึ้นเลย → ดูไฟที่ node H ด้วยมัลติมิเตอร์ (หัวข้อ 6 ของ docs/04)
- ถ้าขึ้นค้างที่ 4095 → D3 กลับด้าน หรือ C_hold ช็อต

## ขั้นที่ 7 — Velocity และ retrigger masking

เปิดหน้า HIT (ตีแล้วจอจะขึ้น `NOW PLAYING`)

| ทดสอบ | ผลที่ต้องได้ |
|-------|--------------|
| เคาะเบา ๆ | `VELOCITY: 20–45`, เสียงค่อย |
| เคาะแรง | `VELOCITY: 90–127`, เสียงดัง |
| เคาะรัวเร็ว ๆ 10 ครั้งใน 1 วินาที | ได้ยินครบ 10 ครั้ง (mask 22 ms) |
| เคาะ 2 ครั้งห่างกัน 5 ms | ได้ยินครั้งเดียว (ถูก mask โดยเจตนา) |

ถ้า velocity ไปเต็ม 127 ตลอด → threshold ต่ำเกินไป ให้รัน `c` (calibrate) หรือลดความไวด้วย trimpot

## ขั้นที่ 8 — ทุกแพด + polyphony

1. ต่อ piezo ครบ 9 ช่อง
2. พิมพ์ `i` ดูว่าแต่ละช่องมี threshold และ peak ของตัวเอง
3. ตีพร้อมกันหลายแพด (ใช้สองมือ) → ต้องดังพร้อมกัน ไม่ตัดกัน
4. ดู `s`: `voices` ต้องขึ้นหลายค่า และ `queue drop` ต้องเป็น 0

## ขั้นที่ 9 — Hi-hat pedal

1. ต่อ pot ตามหัวข้อ 2.7
2. หน้า HOME ดูบรรทัด `HH OPEN 87%`

| ตำแหน่งเหยียบ | ค่าที่ควรเห็น | เสียงที่ได้ |
|----------------|---------------|-------------|
| ปล่อยสุด | `HH OPEN 90–100%` | HH_OPEN.wav |
| กึ่งเหยียบ | `HH HALF 35–65%` | HH_HALF.wav |
| เหยียบสุด | `HH CLOSED 0–25%` | HH_CLOSED.wav |
| เหยียบลงเร็ว ๆ จากปล่อยสุด | ยังขึ้น CLOSED | ได้ยิน HH_CHICK.wav (เสียง "ชิก") |

ถ้าค่าตรงข้าม (ปล่อยสุดได้ 0%) → ตั้ง `HH_PEDAL_INVERT 1` ใน `include/config.h`
ถ้าค่าแกว่ง → เพิ่ม C 100 nF ที่ wiper หรือใช้ Hall sensor

## ขั้นที่ 10 — Calibration

1. **เงียบทั้งห้อง** (อย่าแตะกลอง) → `MENU → CALIBRATE`
2. จอขึ้น `BE QUIET...` แล้ววิ่งไป 100%
3. จอสรุป threshold ทุกช่อง + serial

```
[cal] SNARE      floor   42 -> threshold  146
[cal] SNARE RIM  floor   35 -> threshold  129
```

4. ค่าถูกบันทึกลง NVS → รีเซ็ตแล้วยังอยู่
5. ถ้า threshold สูงเกินจนตีเบาไม่ติด ให้ลด `CAL_MULTIPLIER` (ค่าเริ่มต้น 2.4)

## ขั้นที่ 11 — เปลี่ยนชุดเสียง

กดปุ่ม **KIT** (สั้น = ถัดไป, ค้าง = ก่อนหน้า) → จอขึ้น `LOADING KIT` ~0.3–1 วินาที
แล้วเล่นต่อได้ทันที ตรวจว่าเสียงเปลี่ยนจริงตามชุด (POP/ROCK/HIPHOP/JAZZ)

## ขั้นที่ 12 — ทดสอบภาระหนัก (stress)

1. ตีรัวต่อเนื่อง 30 วินาที
2. ดู `s` ทุกวินาที: `queue drop` ต้อง 0, `i2s err` ต้องไม่เพิ่ม, `heap` ต้องไม่ลดลง (ห้ามมี memory leak)

---

## รวมคำสั่ง serial

| คำสั่ง | ทำอะไร |
|--------|--------|
| `i` | ข้อมูลระบบ + ตาราง threshold/peak ทุกแพด |
| `m` | heap, sample pool, flash |
| `s` | สถิติ (voices, adc rate, drops, errors) |
| `c` | เริ่ม calibration |
| `t` | dump ค่า peak 3 วินาที |
| `d` | เปิด/ปิดสถิติรายวินาที |
| `p0`…`p8` | ยิงเสียงทดสอบแพดนั้นที่ velocity 100 |
| `h` | help |

## ปัญหาที่พบบ่อย (สรุป)

| อาการ | สาเหตุอันดับแรก |
|-------|-----------------|
| ไม่มีเสียงเลย | XSMT ของ PCM5102A ไม่ได้ HIGH |
| เสียงดังข้างเดียว | OUT ของ PAM8403 ต่อไม่ครบ หรือลำโพงขาด |
| ตีแล้วเสียงไม่ตรงแพด | สลับสาย CH บน MCP3208 → ดูตาราง docs/03 ข้อ 4 |
| ตีแรงแล้วค่าเต็ม 4095 ตลอด | R_limit หายไป (ต่อ piezo เข้า ADC ตรง ๆ) — อันตราย |
| เสียงแตกตอนตีพร้อมกันหลายแพด | ลด `AUDIO_MAX_VOICES` หรือเพิ่ม `AUDIO_DMA_DESC_NUM` |
| จอค้าง แต่เสียงยังออก | loop task ติด I2C — ลด `UI_REFRESH_MS` ให้มากขึ้น (เช่น 150) |
